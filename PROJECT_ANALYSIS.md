# Анализ CRM-системы для репетиторства

## Стек
Django + SQLite (Railway PostgreSQL в проде)

## Что уже есть

### Модели
- `Tutor` — профиль репетитора
- `Student` — ученик (имя, телефон, telegram, класс, заметки, баланс предоплаты)
- `StudentGroup` — группы учеников
- `Lesson` — занятие (дата, время, длительность, цена, предмет, заметки)
- `Attendance` — посещаемость (present/absent, notes)
- `Payment` — оплата (наличные/перевод/баланс предоплаты, флаг is_balance_payment)

### Функционал
- Календарь (месячный + недельный для мобилки)
- CRUD: ученики, занятия, группы
- Отметка посещаемости с автоматическим списанием предоплаты
- Повторяющиеся занятия (еженедельно, период до 1 года)
- Дашборд: кол-во учеников, прибыль за неделю/месяц/всё время, топ должников
- Отчёт по прибыли за период (по дням, по ученикам, по способу оплаты)
- Список всех долгов + погашение всех долгов ученика разом
- Регистрация/вход

## Чего нет — потенциальные идеи

### Практичные (быстро реализовать)
1. **Цена по умолчанию у ученика** — сейчас цену вводят вручную на каждом занятии. Поле `default_price` у `Student` и автозаполнение при создании занятия.
2. **Архив учеников** — `is_active` есть в модели, но нет UI для просмотра/восстановления архивных учеников.
3. **Поиск по ученикам** — нет поиска в списке учеников/занятий.
4. **Заметки по посещаемости видны** — поле `notes` у `Attendance` есть, но похоже нигде не отображается в UI.

### Крупнее
5. **Экспорт** — выгрузка в Excel/CSV (ученики, платежи, отчёт за период).
6. **Структурированные предметы** — сейчас `subject` просто строка. Можно сделать отдельную модель предметов с привязкой к ученику (что изучает) и фильтрацией занятий по предмету.
7. **Цели ученика** — дата экзамена (ЕГЭ/ОГЭ), целевой балл. Простое поле-два у `Student`.
8. **Учёт расходов** — нет модели для расходов (книги, материалы). Позволит видеть чистую прибыль.

### Сомнительно (обсуждать)
9. Напоминания/уведомления — требует интеграции (Telegram bot / email)
10. Оценки за занятие — добавить поле к `Attendance`

## Самое вероятное к реализации
По ощущению от кода — **цена по умолчанию у ученика** и **архив учеников** выглядят как самые естественные дополнения: инфраструктура уже почти готова, нужны минимальные изменения.

## План реализации

### 1. Цена по умолчанию у ученика
- Добавить поле `default_price` (DecimalField) в модель `Student`
- Добавить поле в форму `StudentForm`
- При создании занятия: если все ученики имеют одинаковую `default_price` — автозаполнять поле `lesson_price` в форме
- Миграция БД

### 2. Архив учеников
- Поле `is_active` у `Student` уже есть
- Изменить `student_delete` view: вместо реального удаления делать `student.is_active = False`
- Добавить страницу архива (`/students/archive/`) со списком неактивных учеников
- Добавить кнопку "Восстановить" которая ставит `is_active = True`
- Добавить ссылку на архив со страницы списка учеников
