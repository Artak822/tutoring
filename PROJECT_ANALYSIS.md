# Анализ CRM-системы для репетиторства

## Стек
Django + SQLite (Railway PostgreSQL в проде)

## Что уже есть

### Модели
- `Tutor` — профиль репетитора
- `Student` — ученик (имя, телефон, telegram, класс, заметки, баланс предоплаты)
- `StudentGroup` — группы учеников
- `Lesson` — занятие (дата, время, длительность, цена, предмет, заметки)
- `Attendance` — посещаемость (present/absent, notes)
- `Payment` — оплата (наличные/перевод/баланс предоплаты, флаг is_balance_payment)

### Функционал
- Календарь (месячный + недельный для мобилки)
- CRUD: ученики, занятия, группы
- Отметка посещаемости с автоматическим списанием предоплаты
- Повторяющиеся занятия (еженедельно, период до 1 года)
- Дашборд: кол-во учеников, прибыль за неделю/месяц/всё время, топ должников
- Отчёт по прибыли за период (по дням, по ученикам, по способу оплаты)
- Список всех долгов + погашение всех долгов ученика разом
- Регистрация/вход
- **Быстрое закрытие занятия** — посещаемость и оплата прямо на странице занятия без переходов (AJAX)

## Сессия: быстрое закрытие занятия + UI-правки

### Быстрое закрытие занятия (quick-close)

**Логика:**
- На странице занятия для каждого ученика — сегментный pill-переключатель «✓ Пришёл / ✗ Не пришёл»
- При «Пришёл»: система проверяет предоплату и автоматически списывает, если достаточно → показывает «500 ₽ (с баланса)»
- Если предоплаты не хватает → появляется форма: поле суммы (предзаполнено ценой занятия) + кнопки «Нал» / «Карта» с SVG-иконками
- Сумма больше цены занятия → излишек идёт на предоплату, затем автоматически гасятся старые долги
- При «Не пришёл»: оплата аннулируется, если была с баланса — возвращается обратно
- Кнопка сброса (круглый крестик) удаляет оплату с возвратом на баланс при необходимости
- Статистика «Присутствовало» и «Общая стоимость» на странице обновляется без перезагрузки

**AJAX-endpoint `quick_lesson_action`** (`POST /lesson/<lesson_pk>/quick-action/<student_pk>/`):
- `mark_present` — посещаемость present + попытка автосписания с баланса
- `mark_absent` — посещаемость absent + возврат балансового платежа + удаление ручных платежей
- `add_payment` — создание платежа (cash/transfer), обработка переплаты, автопогашение старых долгов
- `reset_payment` — удаление платежа с возвратом на баланс если нужно

**Изменённые файлы:**
- `main/views.py` — `quick_lesson_action`, `_payment_to_dict`; в `lesson_detail` добавлен `students_state_json`
- `main/urls.py` — маршрут `lesson/<lesson_pk>/quick-action/<student_pk>/`
- `main/templates/main/lesson_detail.html` — полная переработка секции посещаемости (см. ниже)

### UI lesson_detail.html

**Дизайн:**
- Сегментный переключатель посещаемости: pill с двумя секциями, активная заливается зелёным/красным
- Зона оплаты — всегда одна строка фиксированной высоты (`min-height: 38px`), состояния:
  - Не пришёл / нет отметки: `—`
  - Пришёл, не оплачено: `[инпут] ₽ [иконка нала] [иконка карты]`
  - Оплачено: `500 ₽  наличные  ⊗`
- Кнопки оплаты: наличные = зелёный ghost, карта = синий ghost; при hover заливаются
- Иконки: SVG купюра (нал) и SVG банковская карта (перевод)
- Кнопка сброса: круг 32px, крестик 14px, при hover краснеет
- Анимация: `opacity` fade 0.2s при обновлении состояния; строка затемняется во время запроса (`ql-loading`)
- Мобильная вёрстка: вертикальный список с разделителями вместо горизонтального скролла и вложенных карточек; убран collapsible

**Исправленный баг:**
- Дублирующийся `id="amount-{pk}"` на десктопном и мобильном инпутах — `getElementById` всегда брал скрытый десктопный, пользовательская сумма игнорировалась
- Исправлено: `id` убран, инпут помечен классом `.pay-amount-field`, контейнер — `data-pay-pk`; `submitPayment` ищет видимый контейнер через `offsetParent`

### Список учеников (`student_list.html`)

Badge в футере карточки ученика:
- Долг > 0 → красный «Долг: X ₽»
- Нет долга, но есть предоплата → зелёный «Предоплата: X ₽»
- Ни того ни другого → серый «Без долга»
