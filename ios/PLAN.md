# iOS-приложение «Tutoring» — план работ

Нативный клиент для существующей Django CRM. Бэкенд один и тот же: та же база, та же
бизнес-логика (`main/services.py`), тот же REST API (`main/api_urls.py`).

## Принятые решения

| Вопрос | Решение |
|--------|---------|
| Расположение | `ios/` внутри репозитория `tutoring` (монорепо) |
| Объём v1 | Полный паритет с вебом + нативные возможности (виджет, напоминания, Face ID) |
| Офлайн | Кэш на чтение через SwiftData; запись требует сети |
| Дизайн | Нативный iOS (SF Pro, системные списки/материалы) с фирменным акцентом `#533afd` из `DESIGN.md` |
| Минимальная iOS | 17.0 (SwiftData, Observation, Swift Charts) |
| Язык/UI | Swift 6, SwiftUI, без сторонних зависимостей |

## Архитектура

```
ios/
├── PLAN.md                     — этот файл
├── Tutoring.xcodeproj          — проект (app + widget extension)
├── TutoringCore/               — локальный Swift Package (общий код app + widget)
│   └── Sources/TutoringCore/
│       ├── Models/             — DTO, зеркалящие сериализаторы Django
│       ├── Networking/         — APIClient, Endpoint, APIError, интерцепторы
│       ├── Auth/               — TokenStore (Keychain), сессия
│       ├── Cache/              — SwiftData-модели и репозитории
│       └── Formatting/         — деньги, даты, склонения
└── Tutoring/                   — app target
    ├── App/                    — точка входа, роутинг, TabView
    ├── DesignSystem/           — Theme, Typography, компоненты (Card, MoneyBadge, SegmentedPill)
    ├── Features/
    │   ├── Auth/               — вход, регистрация, выбор сервера
    │   ├── Calendar/           — месяц / неделя / день
    │   ├── Lesson/             — детали занятия + быстрое закрытие
    │   ├── Students/           — список, карточка, форма, архив
    │   ├── Debts/              — должники, погашение
    │   ├── Groups/             — группы
    │   ├── Reports/            — дашборд + отчёт по прибыли (Swift Charts)
    │   └── Settings/           — профиль, тема, Face ID, выход
    └── TutoringWidget/         — виджет «занятия сегодня»
```

Слои: `View` (SwiftUI) → `@Observable ViewModel` → `Repository` (сеть + кэш) → `APIClient`.
ViewModel'и не знают про URLSession, репозитории не знают про SwiftUI.

## Этап 1. Доработка backend API

Текущий API покрывает не всё, что нужно клиенту. Добавляем (без изменения веб-части,
вся логика через `services.py`):

| Endpoint | Зачем |
|----------|-------|
| `GET /api/v1/lessons/?date_from=&date_to=&student=&status=` | календарь грузит месяц одним запросом; сейчас фильтров нет вообще |
| `GET /api/v1/lessons/calendar/?year=&month=` | компактная сводка по дням для сетки месяца |
| `GET /api/v1/lessons/{id}/state/` | состояние всех учеников занятия (посещаемость + оплата) одним запросом — то, что веб отдаёт как `students_state_json` |
| `POST /api/v1/lessons/recurring/` | повторяющиеся занятия (перенос логики из `recurring_lesson_create`) |
| `GET /api/v1/students/debts/` | список должников с суммами |
| `POST /api/v1/students/{id}/clear-debts/` | погашение всех долгов ученика |
| `GET /api/v1/students/?is_active=&search=` | архив и поиск |
| `POST /api/v1/students/{id}/restore/` | восстановление из архива |
| `POST /api/v1/auth/logout/` | удаление токена устройства |
| `GET /api/v1/meta/` | версия API + справочники (`payment_method`, `cancellation_reason`) с человекочитаемыми названиями |

Плюс:
- `django-filter` не нужен — фильтры делаем вручную в `get_queryset`, чтобы не тянуть зависимость;
- `?page_size=` для пагинации (клиенту нужны разные размеры страниц);
- тесты `main/tests.py` на скоуп по репетитору (чужие данные не должны быть видны) и на quick-action;
- CORS не нужен — нативный клиент не браузер.

**Проверка безопасности:** каждый новый эндпоинт скоупится через `TutorScopedViewSetMixin`,
чужие `student_id`/`lesson_id` дают 404, а не 403 с утечкой факта существования.

## Этап 2. Каркас приложения

- Xcode-проект с синхронизированными группами (файлы подхватываются из ФС, не надо править `pbxproj`).
- `TutoringCore`: `APIClient` на `async/await` + `URLSession`, типизированные ошибки,
  автоматическая подстановка `Authorization: Token <key>`, единая обработка 401 → разлогин.
- Экран выбора сервера (прод / локальный `http://localhost:8000` для отладки) — в Debug-сборке.
- Вход и регистрация, токен в Keychain (`kSecAttrAccessibleAfterFirstUnlock`).
- Дизайн-система: цвета из `DESIGN.md` с light/dark вариантами, типографика на SF Pro,
  компоненты `Card`, `MoneyText`, `StatusPill`, `EmptyState`, `LoadingRow`.

## Этап 3. Календарь и занятие (ядро продукта)

- Месячная сетка с точками-индикаторами и суммой за день; свайп между месяцами.
- Недельный и дневной режим; «сегодня» по умолчанию.
- Экран занятия: список учеников, у каждого — сегментный переключатель «Пришёл / Не пришёл»
  и строка оплаты (сумма + «Нал» / «Карта»), точное повторение web-логики quick-close.
- Оптимистичные обновления с откатом при ошибке, тактильный отклик на успешную отметку.
- Создание/редактирование занятия, повторяющиеся занятия, отмена с причиной и восстановление.

## Этап 4. Ученики и долги

- Список с поиском, бейдж «Долг / Предоплата / Без долга» (как в вебе).
- Карточка ученика: контакты, баланс, история занятий и платежей, долг.
- Создание/редактирование/архив/восстановление, звонок и Telegram по тапу.
- Экран должников: сортировка по сумме, общий итог, погашение всех долгов ученика.

## Этап 5. Группы, дашборд, отчёты

- Группы: список, состав, CRUD.
- Дашборд: ученики, прибыль за неделю/месяц/всё время, занятия.
- Отчёт по прибыли: выбор периода, Swift Charts (по дням), разбивка по ученикам и способам оплаты.

## Этап 6. Офлайн-кэш

- SwiftData-модели `CachedStudent`, `CachedLesson`, `CachedPayment` + отметка времени синхронизации.
- Репозитории отдают кэш мгновенно и обновляют из сети (stale-while-revalidate).
- Индикатор «данные от HH:mm» при отсутствии сети; действия записи блокируются с понятным сообщением.

## Этап 7. Нативные возможности

- **Виджет** «Сегодня»: ближайшие занятия, кто не отмечен. Данные через App Group.
- **Локальные уведомления**: напоминание за N минут до занятия, вечерний разбор неотмеченных занятий.
- **Face ID / Touch ID** на вход в приложение (опция в настройках).
- **App Intents / Spotlight**: «Показать занятия на сегодня».

> Виджет и App Group требуют учётной записи Apple Developer (достаточно бесплатной) для
> подписи. Если её нет — этап 7 сокращается до уведомлений и Face ID, остальное не блокируется.

## Этап 8. Проверка

- Юнит-тесты на `TutoringCore` (парсинг, ошибки, деньги как `Decimal`).
- Прогон на симуляторе iPhone 17 против локального Django с реальными данными.
- Проверка тёмной темы, Dynamic Type, VoiceOver на ключевых экранах.

## Риски и решения

| Риск | Решение |
|------|---------|
| Деньги как `Double` дают копеечные расхождения | Везде `Decimal`, API уже отдаёт суммы строками |
| Расхождение логики предоплаты между вебом и iOS | Клиент никогда не считает баланс сам — только показывает ответ `services.py` |
| Пагинация DRF (20 записей) незаметно обрежет календарь | Явная работа с `next`, для календаря — отдельный непагинированный эндпоинт |
| Токен без срока жизни | `logout` удаляет токен; при 401 клиент чистит Keychain и возвращает на экран входа |
| Часовые пояса | Сервер в `Europe/Moscow`, даты занятий — «календарные» без времени UTC; клиент не конвертирует `date`/`time` |

## Открытый вопрос

Адрес продового стенда: `https://tutoringforartak.up.railway.app` отвечает 404
«Application not found». Нужен актуальный URL (или починка деплоя) — до этого клиент
разрабатывается против локального сервера.
